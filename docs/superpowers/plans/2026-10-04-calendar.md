# Sanctra Calendar Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a fully usable native Calendar for tasks, events and exams, with verified two-way Google Calendar synchronization.

**Architecture:** Project existing tasks and exam goals into calendar entries without duplicating their storage; persist personal CalendarEvent records with account isolation. A separate Cloudflare Calendar Worker handles OAuth, encrypted credentials, durable synchronization and conflict resolution. Native functionality ships independently of Google configuration.

**Tech Stack:** Existing React 19, TypeScript, Vite, Firebase Auth/Firestore, Sanctra CSS tokens; @js-temporal/polyfill 0.5.1 for timezone arithmetic; Cloudflare Workers, D1, Queues and scheduled triggers.

**Spec:** `docs/superpowers/specs/2026-10-04-calendar-design.md` (approved October 4, 2026).

## Global Constraints

- Use Sanctra's existing glass clarity, theme colours, quiet typography and controls.
- Tasks remain the task-management view; exam configuration remains in Edit profile.
- Keep Tasks and ExamGoals as sources of truth; derive their calendar entries rather than copying them into a second task list.
- Scope entries to the signed-in account and active desk using belongsToWorkspace.
- All-day date strings must never be converted through UTC midnight.
- Tokens and secrets never enter app caches, logs or client-readable Firestore documents.
- Ordinary Google events import as events, not todos.
- Avoid modifying attendee lists, invitations or conferencing information when editing imported events.
- Disconnect revokes credentials, stops watchers and queues, and preserves native data and existing Google events by default.
- No claim of two-way sync based only on mocked responses.
- Preserve unrelated current working-tree edits. Execution method: Native, as previously selected by the user.

## Review Focus

1. Account switch during an async load: stale responses must not populate the next account; Task 2 tests this.
2. DST gap/fold or overnight event: selected date and duration must remain correct; Task 1 tests this.
3. Remote delete of a linked task/exam: do not erase the todo or goal; Task 6 tests this.
4. Local and remote edits while offline: display conflict instead of silently overwriting; Task 6 tests this.
5. Replayed webhook or retried export: exactly one mapped event and no credentials disclosed; Tasks 5 and 6 test this.

### Task 1: Calendar contracts and timezone projection

**Files:** Create calendar types/dates/projection/eventValidation modules, `tests/calendarProjection.test.ts`; modify package.json/pnpm-lock.yaml for Temporal 0.5.1.

**Interfaces:**
- `CalendarEvent`: id/workspaceId/title/notes/location/timezone, timed ISO instants or all-day date interval, recurrence `{frequency:'daily'|'weekly',until?:string}`, exception map by occurrence date, createdAt/updatedAt/revision/deletedAt, optional remote metadata.
- `CalendarEntry`: stable id, sourceId, kind ('task'|'event'|'exam'), title, date, allDay, optional start/end instants, completed, readonly, occurrence key.
- `getMonthDates(date:string):string[]` returns 42 Monday-first dates.
- `projectCalendarEntries({tasks,goals,events,workspaceId,legacySpaceId,timezone,rangeStart,rangeEnd}):CalendarEntry[]` uses an exclusive rangeEnd.
- `validateCalendarEvent(event:CalendarEvent):string[]`, `localSlotToInstants(date,start,end,timezone):{start:string,end:string}` rejects nonexistent times and asks for explicit offset on ambiguous times.

**Interfaces:**

## Plan self-review

All approved UI, persistence, authentication, sync and acceptance requirements map to Tasks 1–7. Native event creation and recurring edits are separate from task projection. Account-data array writes and Google remote mutations use concurrency preconditions; no hidden direct deletion of goals/tasks on remote cancellation. Interface names are shared consistently. Task 7 has a live verification gate, and Tasks 3–4 supply an independently usable native checkpoint if Google configuration is blocked.
