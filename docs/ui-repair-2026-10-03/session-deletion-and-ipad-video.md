# Session deletion and iPad video repair

Session deletion previously changed private history without touching the verified ranking clock. It now deducts the deleted record from the current UTC day/week/month counters before removing the local session, using an atomic deletion receipt to prevent duplicate deductions from retries or another device. Manual sessions created after the historical migration earn no competitive credit and are excluded. Timer durations are retained across future personal-history edits. A failed ranking transaction keeps the session and shows a reconnect message. Existing records lack a per-session server credit ledger, so their bounded saved duration is used for the deduction, capped by the available score.

Firestore Rules permit only downward changes to the owner's three score counters, preserving the timer lease, last server timestamp and integrity flags. Attempts to increase a score, edit flags, modify another account, or overwrite a deletion receipt are rejected. Normal server-bounded timer increments remain unchanged. Live disposable-account checks verified both the permitted deduction and rejection of forged increases. The historical-migration audit showed no historical deletion discrepancy. A separate check of closed, idle clocks found one account with 1,765 excess day seconds beyond remaining saved sessions. A compare-and-set repair removed that stale credit from affected periods, preserving all other clock fields and retaining a private backup. Active or paused timers were excluded.

All hosted MP4 scenes returned successful video responses, but their byte-range requests returned full files. Apple documents byte-range support as necessary for Safari HTTP video delivery. Native Safari now selects HLS playlists and complete segments generated from the existing footage without recompressing it; other browsers keep MP4 playback. Media caching and playlist MIME types are explicit. Autoplay rejection no longer permanently removes the video, and later taps retry muted, inline playback. Reduced-motion settings remain respected.

The native-HLS route was tested in the in-app browser at 1024×768: the stream reached readyState 4, was playing, and currentTime advanced. After publishing, the live hero also selected its HLS stream and played with readyState 4. This is browser-engine verification, not a test on the user's physical iPad. The time-of-day button was removed from the public home page. All eight production HLS playlists and their initial segments returned the correct media types; one transient segment response succeeded on retry.

Validation: 125 application tests, 41 Firestore Rules tests, production database smoke checks, and the landing build/SEO checks passed.
